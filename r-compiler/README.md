# r-compiler

Go-сервис, который выполняет присланный R-код и возвращает готовый PNG-график. Изолированная «песочница» для рендеринга визуализаций, которые ИИ-агент сайта генерирует на R — сам сервис никакой ИИ-логики не содержит, только запуск `Rscript` в контейнере с преднастроенным набором пакетов.

Кто его вызывает и что происходит при недоступности сервиса — см. [`../docs/integrations.md`](../docs/integrations.md) (эндпоинт вызывается из `src/app/api/agent/r-compile/route.ts`, таймаут на стороне сайта — 35с, ретраев нет).

## Как это устроено (по факту чтения `main.go`)

Сервис — обычный `net/http` сервер (без фреймворка) с двумя маршрутами.

### `GET /health`
Возвращает `{"status": "ok"}`, без проверки реальной работоспособности R.

### `POST /compile`
Request:
```json
{
  "code": "ggplot(...) + geom_point()",
  "files": [
    { "name": "data.csv", "content_b64": "<base64>" }
  ]
}
```
- `code` — обязателен, тело R-скрипта (без него — `400`).
- `files` — опционально, каждый файл декодируется из base64 и кладётся во временную директорию рядом со скриптом (имя очищается через `filepath.Base`, так что попытка выйти за пределы директории через `../` не сработает).

Что делает сервер под капотом:
1. Создаёт временную директорию (`ioutil.TempDir`), удаляется в конце (`defer os.RemoveAll`).
2. Пишет присланные файлы в неё.
3. Оборачивает `code` в служебный скрипт: `setwd(tmpDir)`, `library(Cairo)`, `CairoPNG("output.png", width=1400, height=1000, res=120)`, вставляет пользовательский код, `dev.off()`. То есть **пользовательский R-код не должен сам открывать графическое устройство** — устройство уже открыто снаружи, скрипту достаточно построить график (последнее выражение) и он попадёт в `output.png`.
4. Запускает `Rscript script.R` через `exec.CommandContext` с жёстким таймаутом **30 секунд** (`context.WithTimeout`, `maxExecTime`). При превышении — `exit_code: 124`.
5. Если `output.png` создан и exit code == 0 — читает файл, кодирует в base64, возвращает как `image`.

Response:
```json
{
  "success": true,
  "image": "<base64 PNG или пусто>",
  "log": "stdout + stderr R-процесса",
  "exit_code": 0
}
```

Никакой аутентификации/авторизации у сервиса нет — предполагается, что он недоступен снаружи докер-сети (см. ниже).

## Сборка и запуск локально

Из `Dockerfile`: образ собирается на `rocker/r-ver:4.4.0` (Debian + R 4.4.0, оптимизирован под быструю бинарную установку пакетов через Posit Package Manager), внутри дополнительно ставится Go (`apt-get install golang`) для компиляции самого HTTP-сервера.

```bash
# из директории r-compiler/
docker build -t r-compiler .
docker run --rm -p 8000:8000 r-compiler

# проверка
curl http://localhost:8000/health
curl -X POST http://localhost:8000/compile \
  -H "Content-Type: application/json" \
  -d '{"code": "plot(1:10)"}'
```

Сборка образа медленная (компилируется/ставится ~35 R-пакетов из исходников или бинарей PPM) и не проверялась целиком в рамках этого аудита — только чтение `Dockerfile`/`main.go`.

В `docker-compose.yml` сервис поднимается без проброса портов наружу (`# NO ports exposed - internal only via Docker network`) — доступен только другим контейнерам сети `cloudflare` по имени `r-compiler:8000`. Порт настраивается через `PORT` (fallback `8000`), но в compose эта переменная не задаётся — используется дефолт.

## Ключевые файлы

- `main.go` — весь сервис (HTTP-сервер, обёртка скрипта, запуск `Rscript`).
- `Dockerfile` — базовый образ `rocker/r-ver:4.4.0`, системные зависимости (Cairo, X11/Xvfb, libcurl, libxml2 и т.д.), установка Go, список R-пакетов (`ggplot2`, `plotly`, `dplyr`, `tidyr`, `corrplot`, `pheatmap`, `treemap`, `igraph`, `viridis`, `Cairo`, `svglite`, `ggridges`, `ggrepel`, `patchwork`, `gridExtra`, `reshape2`, `forcats`, `lubridate`, `fmsb`, `waffle`, `waterfalls`, `wordcloud`, `ggExtra`, `ggalt`, `ggthemes`, `showtext`, `ggsci`, `hrbrthemes`, `esquisse` и др.).

Промпт/системные инструкции для того, какой именно R-код генерировать под этот компилятор (стиль графиков, запрет на `png()`/`ggsave()`, разрешённые и запрещённые пакеты) — не здесь, а в [`../r/`](../r/) (`r-skill.md`, `r-knowledge-compact.md`), которые подключаются к промпту ИИ-агента через `src/lib/agent/knowledge/loader.ts`.

## Известные ограничения

- **Нет аутентификации** — любой, кто достучится до порта 8000 внутри сети, может выполнить произвольный R-код на сервере (RCE by design, митигируется только тем, что порт не проброшен наружу и сеть внутренняя).
- **Нет ограничения ресурсов** (CPU/память/дисковые операции) внутри самого Go-кода — единственная защита от зависшего скрипта — таймаут 30с на весь процесс.
- Если `Rscript` завершился с кодом 0, но `output.png` не создан (пользовательский код не построил график) — сервис возвращает `success: false` с соответствующим сообщением в `log`, а не ошибку HTTP.
- Список R-пакетов зафиксирован на этапе сборки образа — добавить новый пакет во время выполнения нельзя, нужен ребилд.
- Реальный `docker build`/`docker run` в рамках этого аудита не выполнялся (описание — по чтению `Dockerfile`/`main.go`).
