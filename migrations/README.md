# migrations/ (корень репозитория)

## Что тут лежит

Два «сырых» SQL-файла, написанные для ручного выполнения в SQL-редакторе Supabase: `2026-04-21-staged-pipeline.sql` и `2026-05-02-r-sessions.sql`.

## ⚠️ Важно: это не актуальный источник схемы

**Эта папка не отражает реальную структуру базы данных, которой сейчас пользуется приложение.** Единственный источник истины — `prisma/schema.prisma` (см. [`../prisma/README.md`](../prisma/README.md)), применяемый через `npx prisma db push` (см. [`../docs/data_model.md`](../docs/data_model.md) и [`../docs/REVIEW.md`](../docs/REVIEW.md), пункт 10). Файлы в этой папке — это исторические artefacts более раннего этапа проекта, когда БД была Supabase (Postgres + Supabase-специфичные конвенции), а не текущий self-hosted Postgres через Prisma:

- Названия таблиц здесь — `snake_case`/lowercase (`agent_uploads`), тогда как код приложения через Prisma Client обращается к `PascalCase`-таблицам, которые генерирует `schema.prisma` (`AgentUpload`).
- Код приложения (`src/lib/db.ts` и др.) НЕ выполняет эти SQL-файлы ни при старте, ни при деплое — `deploy.sh` вызывает только `prisma db push`.

Не выполняйте эти файлы против текущей продовой БД — они опишут таблицы, несовместимые с тем, что ожидает Prisma Client.

## Ключевые файлы

| Файл | Что в нём |
|---|---|
| `2026-04-21-staged-pipeline.sql` | Добавляет `stage_json` в `agent_sessions` и создаёт таблицу `agent_uploads` (кэш распарсенных PDF с TTL `expires_at`). Согласно `docs/data_model.md`, в файле есть закомментированный `pg_cron`-джоб на удаление просроченных записей, который никогда не был включён — соответствующей автоочистки в текущей Prisma-модели `AgentUpload` тоже нет. |
| `2026-05-02-r-sessions.sql` | Создаёт таблицу `RSession` (история сессий R Studio) с триггером на автообновление `updated_at`. В текущей схеме эта модель существует в `schema.prisma` под тем же именем `RSession`, но управляется исключительно через Prisma/`db push`, а не через этот файл. |

## Известные ограничения / технический долг

Сам факт наличия этих файлов в репозитории — риск: человек или ИИ-агент может принять их за актуальное описание схемы и применить буквально, получив несовместимую с Prisma Client структуру БД. Требует уточнения у владельца: применялись ли эти файлы когда-либо к текущей продовой БД, и можно ли их удалить из репозитория, чтобы не вводить в заблуждение (см. [`../docs/REVIEW.md`](../docs/REVIEW.md), пункт 10, и [`../docs/data_model.md`](../docs/data_model.md), примечание в начале документа).
