# src/app/[locale]/citations/

## Что тут лежит

Один файл — `page.tsx` (920 строк, клиентский компонент, без вложенных файлов/подпапок) — менеджер библиографии. Указан отдельно от общего README `[locale]/`, т.к. содержит полноценную логику трёх режимов работы, а не просто рендерит импортированный компонент.

## Зачем существует

Даёт три связанных, но разных способа собрать список источников для отчёта — переключаются вкладками внутри одной страницы (`activeTab`):

| Вкладка | Что делает | Какой API дёргает |
|---|---|---|
| **Search** | Прямой поиск по CrossRef/arXiv/DOI и добавление найденного в личную библиотеку. | `GET /api/citations/search` |
| **Scholar** | AI-поиск публикаций (создаёт `AgentSession` с `doc_type=literature_search`, тот же механизм, что и `/agent/scholar/[id]`). | `POST /api/agent/scholar/sessions`, `POST /api/agent/scholar/search` |
| **Library** | Личная коллекция сохранённых цитат — тегирование, избранное, коллекции, копирование BibTeX. | `GET/POST /api/citations`, `PATCH/DELETE /api/citations/[id]` |

Полный контракт всех эндпоинтов — [`docs/api_reference.md`](../../../../docs/api_reference.md), раздел 7.

## Известные ограничения

- Один монолитный файл на 920 строк без разбиения на подкомпоненты — весь стейт (три вкладки, формы, модалки) живёт в одном компоненте.
- `POST /api/agent/scholar/search` (вкладка Scholar) не проверяет, что запрошенная `AgentSession` принадлежит вызывающему пользователю — можно прочитать чужую scholar-сессию по угаданному/известному id — [`docs/REVIEW.md`](../../../../docs/REVIEW.md), пункт 7.
