# src/app/[locale]/billings/

## Что тут лежит

Один файл — `page.tsx` (563 строки, клиентский компонент, без вложенных файлов) — страница тарифов и оформления подписки/пополнения.

## Зачем существует

Показывает тарифную сетку (`PLAN_STATIC`: free/plus/pro/ultra — лимиты по символам/отчётам/визуалам захардкожены в коде страницы как справочный текст, реальные лимиты для конкретного пользователя приходят отдельно из `GET /api/auth/me` → `limits`), даёт переключать помесячную/годовую оплату и валюту (KZT/USD/RUB), и по нажатию инициирует чекаут через `POST /api/billing/checkout` (Kaspi или CryptoCloud в зависимости от конфигурации — контракт в [`docs/api_reference.md`](../../../../docs/api_reference.md), раздел 9). Также отображает историю транзакций/чеков (`GET /api/billing/stats`) со ссылками на PDF-чек (`/api/billing/receipt/[id]`).

## Известные ограничения

- Курс USD→KZT запрашивается прямо с клиента напрямую у стороннего бесплатного API (`https://open.er-api.com/v6/latest/USD`, без ключа) с захардкоженным фоллбэком `495`, если запрос не удался — то же самое (с другим фоллбэком, `480`) продублировано в `src/app/api/billing/webhook/route.ts` и `src/app/[locale]/dashboard/actions.ts` — три независимых места с одним и тем же внешним вызовом и разными запасными значениями; см. [`docs/integrations.md`](../../../../docs/integrations.md), раздел про курсы валют.
- Тексты тарифов/лимитов на странице статичны (`PLAN_STATIC` в коде компонента) — не проверялось, синхронизируются ли они вручную с реальными `PLAN_LIMITS` в `src/lib/db.ts`, которые фактически применяются при списании.
- Один файл без вложенных подкомпонентов.
