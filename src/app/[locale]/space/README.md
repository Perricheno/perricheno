# src/app/[locale]/space/

## Что тут лежит

UI совместного LaTeX-редактора проектов ("Space" — единица работы, см. [`docs/glossary.md`](../../../../docs/glossary.md)): дашборд списка проектов, сам редактор (файловое дерево + CodeMirror + превью PDF + лог компиляции), история версий, приглашения соавторов и публичный read-only просмотр.

## Зачем существует

Отдельный от Agent продукт — не пошаговая генерация отчёта, а Overleaf-подобное редактирование `.tex`-проекта вручную, с реал-тайм совместным редактированием через CRDT (Yjs) поверх отдельного `ws-server` (см. [`docs/integrations.md`](../../../../docs/integrations.md)). Данные и права доступа (`owner`/`editor`/`viewer`) — через `src/lib/space-db.ts`, компиляция — через `POST /api/space/[id]/compile` (контракт в [`docs/api_reference.md`](../../../../docs/api_reference.md), раздел 8).

## Ключевые файлы и подпапки

| Путь | Что показывает |
|---|---|
| `page.tsx` | Дашборд `/space` — список проектов пользователя (карточки, поиск, создание нового). |
| `NewSpaceModal.tsx` | Модалка создания проекта: выбор шаблона (blank/research/thesis/beamer) и движка компиляции (pdflatex/xelatex/lualatex). |
| `SpaceCard.tsx` | Карточка проекта в дашборде — превью, дата изменения, компилятор, число соавторов, меню действий (дублировать/удалить/поделиться). |
| `[spaceId]/page.tsx` | Server-компонент: проверяет сессию и права владения, подгружает файлы проекта и рендерит `SpaceEditor`. |
| `[spaceId]/SpaceEditor.tsx` | Главный клиентский компонент редактора — вкладки открытых файлов, переключение между обычным и Yjs-редактором, панель соавторов/приглашений, компиляция. |
| `[spaceId]/components/TopBar.tsx` | Верхняя панель редактора: имя проекта, кнопка компиляции со статусом, история, шаринг, экспорт. |
| `[spaceId]/components/FileTree.tsx` | Дерево файлов проекта (создание/переименование/удаление). |
| `[spaceId]/components/LatexEditor.tsx` | Обычный (не совместный) редактор `.tex` на CodeMirror — подсветка синтаксиса, тема в стиле Perricheno. |
| `[spaceId]/components/YjsLatexEditor.tsx` | Совместный редактор на CodeMirror + `y-codemirror.next` — курсоры/правки других участников в реальном времени поверх общего `Y.Doc`. |
| `[spaceId]/components/PdfPreview.tsx` | Просмотрщик скомпилированного PDF (зум, переход по номеру страницы из лога ошибок). |
| `[spaceId]/components/CompilerLog.tsx` | Панель лога компиляции LaTeX — парсит и подсвечивает ошибки/предупреждения с привязкой к файлу/строке. |
| `[spaceId]/hooks/useYjsSpace.ts` | Хук подключения к `ws-server`: поднимает `Y.Doc` + `WebsocketProvider`, отдаёт статус соединения (`connecting`/`connected`/`disconnected`) и флаг `synced`. |
| `[spaceId]/history/page.tsx` | Список версий проекта с возможностью просмотра диффа и отката (`restore`). |
| `invite/[token]/page.tsx` | Экран принятия приглашения соавтора по токену — требует логина, затем добавляет пользователя в проект. |
| `pub/[shareId]/page.tsx` | Публичный read-only просмотр проекта по `share_id` — переиспользует тот же `SpaceEditor` с `userId=-1` (запрет записи обеспечивается на уровне API, не UI). |

## Известные ограничения

- Один и тот же компонент `SpaceEditor` используется и для владельца/соавторов, и для публичного read-only просмотра (`pub/[shareId]`) — блокировка записи полагается на проверки в API, а не на условный рендер UI; отдельно не проверялось, скрыты ли в read-only режиме элементы управления (кнопка компиляции, редактирование файлов) на уровне интерфейса.
- Матрица прав `owner`/`editor`/`viewer` и связанные бизнес-правила — подробно в [`docs/business_logic.md`](../../../../docs/business_logic.md), раздел 7; в этом README не дублируется.
- `ws-server` (Yjs) — публично доступный порт с уязвимой транзитивной зависимостью `ws` (DoS) — [`docs/REVIEW.md`](../../../../docs/REVIEW.md), пункт 8.
- Ни одного теста на права доступа/совместное редактирование — [`docs/REVIEW.md`](../../../../docs/REVIEW.md), раздел «Отсутствие тестов на критичную логику».
