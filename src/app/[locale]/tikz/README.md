# src/app/[locale]/tikz/

## Что тут лежит

UI генератора концептуальных диаграмм в LaTeX-пакете TikZ (`docs/glossary.md`: «TikZ studio») — mind map, concept map, иерархии, схемы процессов и т.п. Каталог типов диаграмм — `types.ts` (`VISUALS`, сгруппированы по `CATEGORIES`: Structure, Process и др.).

## Зачем существует

Самостоятельный, не привязанный к Agent-сессии инструмент: один промпт + выбор типа диаграммы → `POST /api/tikz/generate` → TikZ-код и скомпилированный PDF/превью. В отличие от `agent/`, `space/` и `r/`, здесь нет персистентных сессий — состояние живёт только в React-стейте страницы на время сессии браузера (нет своей папки `[sessionId]`, `RSession`-подобной модели в БД не заведено).

## Ключевые файлы

| Файл | Что показывает |
|---|---|
| `page.tsx` | Единственный экран `/tikz`: поле промпта, выбор типа диаграммы, результат генерации — всё на одной странице. |
| `types.ts` | Типы и статический каталог `VISUALS`/`CATEGORIES` — id, имя, категория, короткое описание каждого типа диаграммы. |
| `CategorySection.tsx` | Сворачиваемая секция каталога типов, сгруппированных по категории. |
| `VisualCard.tsx` | Одна карточка типа диаграммы (превью названия/описания, состояние выбран/не выбран) — переиспользуется и в `CategorySection`, и в `TypeSheet`. |
| `TypeSheet.tsx` | Выезжающий снизу шит с полным каталогом типов (мобильный/компактный аналог `CategorySection`). |
| `ResultPanel.tsx` | Панель результата: TikZ-код, превью PDF, копирование, скачивание `.tex`/`.pdf`, перегенерация. |

## Известные ограничения

- Отсутствие персистентных сессий (в отличие от `agent`/`space`/`r`) означает, что результат генерации теряется при обновлении страницы — не проверялось, ожидаемое ли это поведение или отсутствующая фича.
- Специфичных находок по этому каталогу в `docs/REVIEW.md` нет.
- Ни одного теста на эту логику.
