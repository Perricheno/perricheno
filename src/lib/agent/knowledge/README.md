# src/lib/agent/knowledge/

## Что тут лежит

Набор Markdown-файлов с готовыми правилами/примерами кода плюс `loader.ts`, который читает их с диска и склеивает в один текстовый блок для подстановки в системный промпт LLM. Это не документация для разработчиков — эти `.md` файлы **являются частью промпта**, который видит модель во время генерации.

## Зачем существует

Вместо того чтобы держать правила типографики (казахский/русский LaTeX) или стандарты качества графиков (R/Python) прямо в строках промпта внутри `stage3_draft.ts`, их вынесли в отдельные `.md`-файлы — так их проще редактировать не трогая код стадий.

## Как это используется на самом деле (по коду `loader.ts`)

`loader.ts` экспортирует две функции:

- **`getLatexKnowledge()`** — читает **все** `.md`-файлы из `latex/` (сейчас там один файл, `latex_languages.md`), склеивает их с заголовком `=== LATEX WRITING & LANGUAGE RULES ===` и возвращает как строку. Вызывается **только** из `../pipeline/stage3_draft.ts` (стадия 3 — черновик секций) — единственное место в agent-конвейере, куда попадает эта база знаний.
- **`getVisualKnowledge()`** — собирает более широкий блок: `visuals/libraries.md` (список предустановленных R/Python-библиотек), все `.md` из `visuals/r/` и `visuals/python/`, а **дополнительно** два файла вне этой папки — `r/r-skill.md` и `r/r-knowledge-compact.md` в корне репозитория (`process.cwd()/r/...`). Возвращает всё под заголовком `=== VISUALIZATION KNOWLEDGE BASE ===`. Эта функция **не вызывается из agent-конвейера** (`stage2_6_r_figures.ts` её не импортирует) — она используется в двух других местах: `src/app/api/agent/visualize/generate-code/route.ts` и `src/app/api/r/generate/route.ts` (генерация графиков в разделе R Studio / визуализаций).

Обе функции оборачивают чтение файлов в `try/catch` и при ошибке молча возвращают `""` (плюс `console.error`), то есть отсутствие файла не роняет пайплайн, а просто оставляет модель без этой части знаний.

## Ключевые файлы

| Файл | Что в нём |
|---|---|
| `loader.ts` (74 строки) | Две функции чтения с диска, описанные выше. |
| `latex/latex_languages.md` | Правила LaTeX для казахского/русского/английского: обязательные пакеты (`fontspec`+`babel[kazakh]` для казахского, `babel[russian]` для русского), рекомендованные шрифты с поддержкой казахской кириллицы (Inter, Montserrat, PT Serif/Sans, Roboto). |
| `visuals/libraries.md` | Список предустановленных в компиляторах библиотек: R (`ggplot2`, `dplyr`, `plotly`, `patchwork`, 3D-пакеты и т.д.) и Python (`pandas`, `numpy`, `scipy`, `matplotlib`, `seaborn`, `plotly`), плюс системные шрифты для XeLaTeX. |
| `visuals/python/matplotlib.md` | Пример-эталон качественного academic-графика на Matplotlib/Seaborn (стиль, размер шрифта, убранные спайны) — явно помечен "не копировать код, использовать как ориентир по качеству". |
| `visuals/r/ggplot2.md` | Аналогичный эталонный пример на ggplot2 (`theme_calc`, `geom_smooth`, палитра `ggthemes`). |
| `visuals/r/r_studio_guide.md` | Более широкий гайд по эстетике именно для страницы R Studio: чёрно-белая/grayscale схема (`theme_minimal`/`theme_classic`, `scale_fill_grey`), плюс рецепты ggplot2 по типам графиков. |

## Известные ограничения / технический долг

- Разделение неочевидно из названий папок: `visuals/` знания подключаются НЕ из agent-пайплайна визуалов (`stage2_3_visuals.ts` генерирует TikZ и эту базу не читает), а из отдельных API для R/Python-графиков — при первом чтении кода это легко перепутать.
- Два файла, от которых зависит `getVisualKnowledge()` (`r/r-skill.md`, `r/r-knowledge-compact.md`), физически лежат вне этой директории (в корне репозитория, `r/`) — не проверялось, документированы ли они в другом README; при рефакторинге путей в `loader.ts` их легко забыть.
- Отдельных находок в `docs/REVIEW.md` по этой директории нет.
