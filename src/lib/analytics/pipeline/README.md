# src/lib/analytics/pipeline/

## Что тут лежит

3-стадийный конвейер генерации графиков из реальных данных пользователя: верификация данных → планирование графиков → генерация и выполнение кода. Структурно младший брат `src/lib/agent/pipeline/` (тот же паттерн `runStageN` + оркестратор), но короче и без LaTeX-специфики.

## Зачем существует

Изолирует три независимых шага, чтобы прогресс можно было стримить в UI (через `StageProgress`, общий тип с agent-конвейером) и чтобы явно разделить ответственность: "данные реальные?" — отдельно от "что построить?" — отдельно от "как построить (код)?". Ключевая бизнес-цель, явно закреплённая в промптах каждой стадии — не дать модели сгенерировать код с фиктивными/синтетическими данными. Подробности — [`../../../../docs/business_logic.md`](../../../../docs/business_logic.md), раздел 6 («Конвейер аналитики/графиков»).

## Файлы (1-2 строки на файл)

| Файл | Назначение |
|---|---|
| `index.ts` | `runAnalyticsPipeline()` — оркестратор, вызывает стадии 1→2→3 по порядку, пишет прогресс через переданный `writeProgress()`, возвращает `AnalyticsPipelineResult`. |
| `stage1_verify_data.ts` | Стадия 1: для каждого загруженного файла (параллельно, `CONCURRENCY=3`) LLM определяет, содержит ли файл реальные пригодные для визуализации данные (`verified`, `dataType`, `rowCount`/`columnCount`/`columns`, предупреждения) — защита от генерации графиков по мусорным/пустым файлам. |
| `stage2_plan_charts.ts` | Стадия 2: LLM подбирает, какие из ~40 поддерживаемых типов графиков (`bar`…`3d_scatter`, полный список в `types.ts`) подходят под проверенные на стадии 1 данные, с обоснованием и приоритетом. |
| `stage3_generate.ts` | Стадия 3: последовательная генерация кода (R или Python, в зависимости от `runtime`) под каждый запланированный график; код реально выполняется во внешних сервисах `r-compiler`/`python-compiler` (те же URL, что в `agent/pipeline/stage2_6_r_figures.ts`). Промпт жёстко требует использовать только реальные колонки из плана, без `inplace=True` в Pandas и без `plt.show()`. |
| `types.ts` | Общие типы: `ChartType` (список ~40 типов), `Runtime` (`'R' \| 'Python'`), `AnalyticsSettings`, `DataVerification`, `ChartPlan`, `GeneratedChart`. |

## Известные ограничения / технический долг

Отдельных находок код-ревью по файлам этой директории нет, кроме общей уязвимости `xlsx`, затрагивающей `stage1_verify_data.ts` (см. README родительской папки `../README.md` и [`../../../../docs/REVIEW.md`](../../../../docs/REVIEW.md), пункт 4).
