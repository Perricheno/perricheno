# src/worker/

## Что тут лежит

Один файл, `index.ts` — точка входа отдельного процесса (Docker-сервис `worker`), который слушает очередь BullMQ `"generation"` и исполняет фоновую AI-генерацию, вынесенную из `src/app/api/**/route.ts` в `src/lib/jobs/*` (Фаза 6a).

## Зачем существует

До Фазы 6a генерация отчётов/аналитики/визуалов запускалась как необработанный промис прямо в процессе `perricheno-site` — рестарт или редеплой веб-контейнера убивал незавершённую работу без возможности восстановления (сторож `cleanupStuckSessions` в `src/lib/db.ts` только обнаруживал зависшую сессию через 15 минут, не восстанавливал её). Вынос исполнения в отдельный, независимо перезапускаемый процесс с очередью — то, что реально даёт устойчивость к рестарту: если упадёт/передеплоится `perricheno-site`, задача остаётся в Redis и подхватывается воркером как только он снова готов; если упадёт сам воркер посреди задачи — BullMQ по истечении лока сам переотдаёт задачу (см. идемпотентность в `../lib/jobs/README.md`).

## Как использовать

Не импортируется откуда-либо в приложении — это самостоятельный Node-процесс. Собирается **отдельно от Next.js** через esbuild (`npm run build:worker` → `dist/worker.js`), потому что в проекте нет другого способа резолвить алиас `@/*` в обычном Node-скрипте вне сборки Next.js/Vitest; `--packages=external` бандлит только код из `src/`, реальные npm-пакеты остаются обычными `require()` из `node_modules`, которые копируются в финальный образ отдельно (см. `Dockerfile`, стейдж `worker`). Запускается контейнером `worker` в `docker-compose.yml` (`CMD ["node", "worker.js"]`), без публикации порта наружу (не обслуживает пользовательский HTTP-трафик) — только внутренний `/health` для Docker `HEALTHCHECK`.

## Ключевые файлы

| Файл | Что в нём |
|---|---|
| `index.ts` | Создаёт `Worker('generation', dispatch, {connection, concurrency})` (`@/lib/queue`), `dispatch()` — `switch (job.name)` на 5 обработчиков из `@/lib/jobs/*`; логирует `completed`/`failed`/`error`; поднимает `http.createServer` на `WORKER_HEALTH_PORT` (по умолчанию 8090) только с эндпоинтом `/health`; обрабатывает `SIGTERM`/`SIGINT` через `worker.close()` для аккуратного завершения текущей задачи перед выходом. |

## Известные ограничения / технический долг

- Один процесс, один `Worker` на все 5 типов задач с общим `WORKER_CONCURRENCY` (по умолчанию 3) — нет отдельных лимитов параллелизма на "тяжёлые" (полный 5-стадийный пайплайн отчёта) и "лёгкие" (одна генерация R-графика) задачи. При росте нагрузки может понадобиться разнести на отдельные очереди/воркеры по типу задачи.
- Не имеет собственного набора тестов (Vitest) — проверялся вручную сквозным сценарием (реальный Postgres + Redis + сборка `dist/worker.js`, см. историю коммита Фазы 6a), не автоматизирован в CI.
