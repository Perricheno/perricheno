# src/scripts/

## Что тут лежит

Один файл — `test-settings.ts` (24 строки).

## Зачем существует

Ручной dev-скрипт для проверки, что server actions `getSettings`/`saveSettings` (`src/app/actions.ts`, читают/пишут `src/data/settings.json`) действительно персистентно сохраняют изменения: читает текущие настройки, обновляет `selectedModel` на тестовое значение, перечитывает и сверяет результат в консоли (`SUCCESS`/`FAILURE`).

**Не путать с [`../../scripts/`](../../scripts/README.md) в корне репозитория** — там лежат исторические одноразовые скрипты миграции БД (SQLite → Supabase → self-hosted), не связанные с этим файлом.

## Как использовать

Не часть автоматических тестов и не вызывается из `package.json`. Запускается вручную при отладке, например `npx tsx src/scripts/test-settings.ts`.

## Ключевые файлы

| Файл | Что в нём |
|---|---|
| `test-settings.ts` | Импортирует `getSettings`/`saveSettings` из `../app/actions`, делает связку "прочитать → изменить → прочитать снова → сравнить" и печатает результат в stdout. |

## Известные ограничения / технический долг

Не тест в формальном смысле (не входит ни в один test-runner, в репозитории вообще нет тестового фреймворка — см. [`../../docs/REVIEW.md`](../../docs/REVIEW.md), раздел «Отсутствие тестов на критичную логику»). Полагается на файловую систему (`src/data/settings.json`), поэтому не идемпотентен между параллельными запусками.
