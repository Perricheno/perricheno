# Глоссарий терминов проекта

Термины, специфичные для предметной области Perricheno или сложившиеся исторически в коде и не очевидные из одного только названия. Общеизвестные термины (JWT, webhook, Prisma и т.п.) сюда не включены.

| Термин | Значение |
|---|---|
| **Space** | Единица работы в совместном LaTeX-редакторе — по сути «проект»/«документ» с файлами, версиями, соавторами и share-ссылкой. Модель `Space` в Prisma, UI — раздел `/space`. Не путать с «пространством имён» или «рабочим пространством организации» — организаций в системе нет, Space всегда принадлежит одному владельцу (`owner_id`). |
| **AgentSession** | Одна генерация научного документа целиком (не путать с сессией входа `Session`). Хранит вход (`settings_json`), прогресс по стадиям конвейера (`stage_json`), и результат (`main_tex`, `references_bib`, `visuals_json`). Раздел UI — `/agent`. |
| **Agent pipeline / staged pipeline** | Многостадийный конвейер генерации документа (`src/lib/agent/pipeline/*`): план → извлечение из PDF → генерация визуалов → верификация → R-графики → обогащение по DOI → черновик → сборка → валидация. Подробности — `docs/business_logic.md`. |
| **doc_type** | Тип генерируемого документа. Значения по коду (`src/app/[locale]/agent/types.ts:1`): `research`, `assignment`, `report`, `lab_report`, `literature_review`, `diploma`, `case_study`, `data_analytics`/`data-analytics` (обе формы встречаются — см. `docs/REVIEW.md`), `chat`, `literature_search`. |
| **Style (стиль)** | Уровень сложности/тона генерируемого текста: `simple` \| `medium` \| `phd` (`types.ts:2`). |
| **Scholar** | Раздел поиска научных статей (`/agent/scholar`) — обёртка над внешними API поиска публикаций (см. `docs/integrations.md`), отдельный от менеджера цитат (`Citation`). |
| **Citations / менеджер цитат** | Личная библиотека библиографических записей пользователя (DOI/arXiv/ISBN + готовый BibTeX), с папками-коллекциями. Раздел `/citations`. |
| **RSession (R Studio)** | Отдельная от AgentSession лёгкая сессия генерации статистических графиков через R (`/r`), не часть большого документа. |
| **TikZ studio** | Раздел `/tikz` — генерация концептуальных диаграмм в LaTeX-пакете TikZ. |
| **Canvas** | Раздел `/canvas` — судя по `database.canvas` в корне репозитория и `src/lib/json-canvas.ts`, речь об формате JSON Canvas (аналог Obsidian Canvas, см. файл `Создание аналога Obsidian Canvas.txt` в корне) — визуальный холст для заметок/схем. **Требует уточнения у владельца**: не часть основного изучения кода в рамках этого аудита, документ бизнес-логики Canvas не описывает отдельно. |
| **account_tier / plan_tier** | Два разных поля модели `User`, оба, судя по всему, обозначают тариф пользователя (`free`/`plus`/`pro`/`ultra`). См. дублирование — `docs/REVIEW.md`. |
| **Тарифы (Plus / Pro / Ultra)** | Платные подписочные уровни, ограничивающие `weekly_chars`/`monthly_chars` и другие счётчики. Точные лимиты — `docs/business_logic.md`, раздел 2. |
| **Символы / визуалы / отчёты (chars / visuals / reports)** | Три независимых вида квоты, которые расходует пользователь (`daily_chars_used`, `daily_visuals_used`, `daily_reports_used` в модели `User`) — генерация текста, генерация визуализации, генерация отчёта целиком считаются раздельно. |
| **purchased_* (purchased_chars, purchased_visuals, purchased_reports)** | Разовые платные пакеты сверх тарифного лимита — списываются после исчерпания дневного/недельного/месячного лимита (порядок списания — `docs/business_logic.md`). |
| **Kaspi Pay** | Казахстанская платёжная система (QR/переводы). Была подготовлена как второй способ оплаты (наряду с CryptoCloud), но заброшена и удалена из кода 2026-09-03 (подтверждено владельцем, никогда не была подключена в CI). См. `docs/integrations.md`, раздел 3. |
| **CryptoCloud** | Платёжный процессинг криптовалютных платежей — второй способ оплаты. |
| **ProcessedPayment** | Таблица-дедупликатор платёжных вебхуков (по `order_id`) — единственная защита от повторного начисления за один и тот же платёж. |
| **share_id** | Публичный уникальный идентификатор для «расшаривания» ресурса без авторизации (используется у `AgentSession` и `Space`) — по нему доступна страница `/agent/shared/[shareId]` или `/space/pub/[shareId]`. |
| **Stage / стадия (staged pipeline)** | Один шаг конвейера генерации (`stage1_plan`, `stage2_extract`, ... `stage5_validate`). Прогресс по стадиям (`StageProgress`, `src/lib/agent/stages.ts`) хранится в `AgentSession.stage_json` и опрашивается UI поллингом. |
| **compiler (у Space)** | Движок компиляции LaTeX для конкретного проекта: судя по коду — `pdflatex` (default) и, вероятно, `xelatex` для казахского языка (см. упоминание XeLaTeX в `src/lib/agent/stages.ts:102`) — полный список значений и где он валидируется требует уточнения у владельца. |
| **Template preset (Plain / Academic / IEEE / Elegant / Minimal)** | Пять готовых LaTeX-преамбул для генерируемого документа (`src/lib/agent/templates/presets.ts`). «Academic» жёстко описан в коде как «Astana IT University style» — привязка к конкретному казахстанскому вузу зашита в дефолтный шаблон. |
| **BABEL_LANG_MAP / T2A / babel** | Технические термины LaTeX-типографики: `T2A` — кодировка шрифта для кириллицы, `babel` — пакет локализации переносов/подписей. Используются в `ensureRussianPreamble` для автоматической починки документов на кириллических языках. |
| **PDF staging / agent_uploads** | Промежуточное хранение загруженного пользователем PDF (текст + изображения после OCR) перед использованием агентом — временные записи с `expires_at` (см. `docs/data_model.md`, модель `AgentUpload`). |
| **Internal bot routes (`/api/internal/bot/*`)** | Служебные эндпоинты основного сайта, вызываемые исключительно из контейнера `telegram-bot` по внутренней docker-сети, с отдельной секретной проверкой (не пользовательская сессия). См. `docs/api_reference.md`, раздел Internal/Bot. |
| **BotSession** | Состояние многошагового диалогового сценария Telegram-бота (не то же самое, что веб-`Session`). |
| **AuthRequest** | Промежуточная запись при входе через Telegram (deep-link/поллинг): токен, статус (`pending`/...), данные профиля — используется, пока пользователь подтверждает вход в самом Telegram. |
| **WS / Yjs / ws-server** | Websocket-сервер на базе CRDT-библиотеки Yjs, обеспечивающий совместное редактирование LaTeX-файлов в реальном времени в разделе Space (несколько человек одновременно печатают в одном файле). |
| **R-compiler / Python-compiler / Research-api / PDF-extractor** | Четыре внутренних Go-микросервиса, каждый выполняет один вид «тяжёлой» работы (выполнение R-скрипта, выполнение Python-скрипта, полнотекстовый поиск публикаций, извлечение текста/OCR из PDF) в изолированном контейнере, недоступном снаружи Docker-сети. |
| **cloudflare (docker-сеть)** | Название внутренней Docker-сети в `docker-compose.yml` — не интеграция с Cloudflare API, а просто сеть, через которую наружу торчит (предположительно) Cloudflare Tunnel/прокси перед хостом. Реальных вызовов Cloudflare API в коде не найдено (см. `docs/integrations.md`). |
