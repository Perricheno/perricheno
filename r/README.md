# r/

**Используется в коде** (не мёртвый каталог) — проверено через `grep` по `r-knowledge`/`r-skill` в `src/`: оба файла подключаются в [`../src/lib/agent/knowledge/loader.ts`](../src/lib/agent/knowledge/loader.ts) функцией `getVisualKnowledge()`.

Это не документация для разработчиков и не относится к рантайму HTTP-сервера напрямую — это **база знаний для системного промпта ИИ-агента**, которая скармливается LLM при генерации R-кода для визуализаций (тот код, который потом выполняется в [`../r-compiler/`](../r-compiler/)).

## Файлы

- `r-skill.md` — развёрнутый "skill guide" для роли "Senior R Data Visualization Architect": обязательные ограничения проекта (чёрно-белая палитра `theme_minimal`/`theme_classic`, запрет на `png()`/`ggsave()`/`dev.off()` — устройство уже открыто снаружи компилятором, `set.seed(42)` для воспроизводимости, лимит 80 строк кода), плюс справочник по импорту данных (`readr`, `readxl`), `dplyr`/`tidyr` и т.д.
- `r-knowledge-compact.md` — компактная версия: список разрешённых/запрещённых пакетов (запрещены `plotly`, `htmlwidgets`, `leaflet` и другие HTML/интерактивные — компилятор захватывает только статический graphics device в PNG) и готовые code-паттерны по типам графиков (распределения, сравнения и т.д.).

Оба файла подключаются в промпт **всегда вместе** с остальной базой знаний из `src/lib/agent/knowledge/visuals/` и `src/lib/agent/knowledge/latex/` — `loader.ts` читает их через `path.join(process.cwd(), "r", ...)`, то есть путь жёстко привязан к тому, что эта папка лежит в корне репозитория рядом с `src/`.

## Известные ограничения / что требует уточнения у владельца

- Почему эта база знаний хранится в `r/` в корне репозитория, а не рядом с остальными файлами базы знаний в `src/lib/agent/knowledge/` (`visuals/`, `latex/`) — структурно они делают то же самое (подключаются в системный промпт), но лежат в разных местах. **Требует уточнения у владельца** — возможно, исторический артефакт до переноса остальной базы знаний в `src/`.
- Изменения в этих файлах напрямую влияют на качество/стиль генерируемого R-кода — при правках стоит иметь в виду, что это часть промпт-инжиниринга, а не просто справочная документация.
